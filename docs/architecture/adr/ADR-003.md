# ADR-003 — Stack tecnológico y estándares

- Estado: Propuesto
- Fecha de elaboración: 2026-11-25
- Autores: Briant + Fernando
- Etapa de aplicación: I–III
- Requisitos relacionados: RNF-001, RNF-013, RNF-016, RNF-017, RNF-021, RNF-023

## Contexto

El stack está aprobado. El equipo necesita convenciones compatibles para servicios, integración y validación.

## Fuerzas y restricciones

JavaScript vanilla (ES6+), Node.js, Express, Vue 3 y Vite, PostgreSQL, Sequelize, NATS con JetStream, Redis, Docker y Docker Compose, JWT y bcrypt, Zod, OpenAPI y Swagger UI, Vitest, Supertest, Testcontainers, k6, Pino, SSE, npm y npm Workspaces, Git y GitHub, GitHub Actions, ESLint, Prettier y OpenSpec. Quedan excluidos TypeScript, Drizzle ORM, Prisma y React.

## Alternativas consideradas

ECMAScript Modules unifica el estilo del código de servidor y web. CommonJS es viable para servidor y aumentaría las diferencias entre los dos entornos. Convenciones autónomas reducen coordinación y dificultan revisar contratos.

## Decisión propuesta

Proponer ESM, nombres de archivos `kebab-case`, nombres JavaScript habituales `camelCase` y `PascalCase` para componentes Vue. Separar transporte, casos de uso y persistencia según ADR-002. Validar configuración del entorno en el arranque con Zod y validar entradas en los bordes. Homogeneizar errores HTTP mediante códigos de contrato y correlación, con detalles internos reservados a registros privados. Documentar contratos en OpenAPI y servir Swagger UI en un alcance autorizado. Fijar versiones de las herramientas y dependencias mediante manifiestos y lockfile, y revisar cambios incompatibles.

## Justificación

Son convenciones propuestas que concretan el stack sin sustituirlo ni añadir dependencias.

## Consecuencias positivas

Reduce las diferencias de lectura entre servicios y permite reproducir validaciones.

## Consecuencias negativas

Exige mantener reglas, contratos y versiones compatibles al evolucionar los paquetes.

## Riesgos y mitigaciones

Comprobar contratos y formato en CI. Cualquier dependencia adicional se evalúa como propuesta separada antes de incorporarla.
